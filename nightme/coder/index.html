每轮把 nightme/assigned 队列里的一个 issue 修好、review 过并处理 findings，开成一个能合的 PR。

nightme/coder nightme-coder the messages are instructions to the agent

the workflow file

Arguments

namedefaultrequired
issue * no

Jobs

ship

runs until the run ends · sleep: 5m

idkindstepnote
fix message 
/gtw fix ${{ args.issue }} -y
 从 nightme/assigned 队列里挑一个 issue 交给 agent 修。挑不到（data.issue 为空）这轮就没活干，后面的步骤都跳过。
commit message

if ${{ steps.fix.outputs.data.issue }}

/gtw commit
 提交 agent 的改动。真没东西可提交时 instruct 让 agent 改，改完 resume 这一步。
review message

if ${{ steps.fix.outputs.data.issue }}

/review
 review 本分支与 base 的差异，findings 回到聊天里。链 [omp, codex] 自己降级，不用你手动降级。 只有 outcome 带 unfinished（还有组没跑完）时才走 /review --continue 那一步；重跑本步是一次全新的整审，白做。 no_diff 是异常：fix 本该改出了东西，分支却和 base 一样 —— instruct 让 agent 真正改出来，再跑 commit 和 review； base_unknown 是 base 分支没解析出来，也什么都没 review，先弄清 base 再跑 review；already_running 就用 wait 等它结束再看。
review-continue message

if ${{ steps.review.outputs.data.unfinished }}

/review --continue
 review 的链降级过一轮之后还有组没跑完时，用它收尾：/review --continue 拿本 chat 上一次 review 的记录， 用最后一个 agent 续那些没跑完的组（跑到过 agent 的组续 session，没跑到的重放存下来的 prompt）。 每组只有一次恢复额度，这步失败就用完了。报 no review to continue（daemon 重启过、记录没了）就别再试续跑，让 chat 模型 next 掉本步继续往下走。
commit-revise message

if ${{ steps.fix.outputs.data.issue }}

/gtw commit
 提交 review 后的修改。findings 只修成立且必要的，其余驳回；要修的 instruct 交给 agent 改，改完 resume 这一步。
push message

if ${{ steps.fix.outputs.data.issue }}

/gtw push
 推送分支。本地还有没推的提交时 instruct 让 agent 提交后 resume 这一步。
pr message

if ${{ steps.fix.outputs.data.issue }}

/gtw pr --ready
 开 PR 并把 issue 标成 ready。no_remote_branch：instruct 让 agent 推；no_commits：instruct 让 agent 提交；改完 resume 这一步。
pr-wait wait

if ${{ steps.fix.outputs.data.issue }}

60s
 等平台算完 PR 的 merge state。
pr-view message

if ${{ steps.fix.outputs.data.issue }}

/gtw pr view ${{ steps.pr.outputs.data.pr_number }}
 看 PR 现在能不能合；conflict=1 是正常分支，下面的修复步骤据此处理。
pr-fix message

if ${{ steps.pr-view.outputs.data.conflict }}

PR #${{ steps.pr-view.outputs.data.pr_number }} 有合并冲突。
在这个 worktree 里先 git fetch，再把它的 base 分支（${{ steps.pr-view.outputs.data.base_branch }}）合并进当前分支。
解掉冲突，提交并推送，让这个 PR 变成可合并。
不要关 PR，不要动 issue 的 label。
只有冲突时才让 chat 的 agent 去修。
pr-fix-wait wait

if ${{ steps.pr-view.outputs.data.conflict }}

60s
 等平台重算 merge state。
pr-recheck message

if ${{ steps.pr-view.outputs.data.conflict }}

/gtw pr view ${{ steps.pr-view.outputs.data.pr_number }}
 修完再查一次；还冲突就是没修好，本轮到此为止。
back final message

if ${{ steps.fix.outputs.data.issue }}

/gtw back
 回主仓库目录。下一轮的 fix 必须从 main 开始 —— worktree 里再 fix 会报 already_active。
