fix message 
/gtw fix ${{ args.issue }} -y
 从 nightme/assigned 队列挑一个 open issue，交给 agent 在 worktree 里修。队列空时它报 no_candidate —— 这不是错误，是正常工作流的一个分支：引擎会跳过本轮后面的步、跑 wait 退避 5 分钟，再挑下一个。只有 data.issue 有值，后面的步骤才跑。
commit message

if ${{ steps.fix.outputs.data.issue }}

/gtw commit
 把 agent 的改动提交成 commit。命令会告诉你修改有没有进到 git 里：提交上了是正常；没提交上但活已经干完了（agent 自己提交的）也是正常；outcome 带 error 才是异常（nothing_to_commit），那时再决定要不要让 agent 去改。
review message

if ${{ steps.fix.outputs.data.issue }}

/review
 review 当前分支与默认分支的差异，findings 回到聊天里。本步的 agents 链是 [omp, codex]：先发 /review -a omp，只有 omp 那次是异常 outcome 才自动落到 /review -a codex —— 异常 = 带 error 描述的 failed（429 限流、崩溃，no_diff / base_unknown / already_running，以及 review 报了 findings 但这一轮没改掉的 not_fixed），或状态不是 ok / noop / failed（incomplete、timeout、unknown）；正常结果（ok / noop，或不带 error 描述的 failed）就以 omp 那次的结果收尾，链到此为止；cancelled（用户手动停掉了这一轮）是例外，链直接结束、不降级。action history 里出现 /review -a codex 就说明降级已经发生过，不要再手动降级。链的每次尝试各占本步 budget 的一次机会，一轮 review 最坏耗 2 次；本步被重跑（含 repair）时链从头开始，总是先试 omp。中断看 outcome：被中止（cancelled）时链不会落到 codex，没跑完的组还能续；跑完但有组没跑完（incomplete）时算异常，链已经自动跑过一次 /review -a codex —— 那是一次全新的 review，会顶掉 omp 那次的续跑记录，omp 没跑完的组就再也续不上。两种中断都不要重跑本步：重跑发的是 /review -a omp，-a 与 -c 互斥，等于丢掉已有进度重开 review；要接着把没跑完的组跑完，instruct 让当前 agent 发 /review -c（不带 -a，它续的是这个 chat 里最后一次 review 的组）。already_running 就等它结束。no_diff 是异常：fix 本该改出了东西，分支却和 base 一样 —— instruct 让 agent 真正改出来，再跑 commit 和 review；base_unknown 是 base 分支没解析出来，也什么都没 review，先弄清 base 再跑 review。
commit-revise message

if ${{ steps.fix.outputs.data.issue }}

/gtw commit
 把 review 之后的修改提交成 commit。findings 先评估：只有成立且必要的才修，其余驳回 —— 要修的用 instruct 把这几条 findings 交给 agent 改，改完跑 commit-revise 提交。outcome 不带 error 就是正常：findings 已修好并提交，或没有必须修的 findings —— 结果够用，跑 push 继续；带 error 才是异常（nothing_to_commit：工作区没有改动，findings 还没修好），先让 agent 去改。
push message

if ${{ steps.fix.outputs.data.issue }}

/gtw push
 把分支推到远端。命令会告诉你有没有东西没推：本地已经全部在远端是正常的（可能 agent 自己推过），本地还有没推的才是异常，那时回 commit 那一步。
pr message

if ${{ steps.fix.outputs.data.issue }}

/gtw pr
 给分支开 PR。pr_exists 说明这个分支的 PR 已经开过，这也是正常的，结果够用，跑 back 继续；no_remote_branch 或 no_commits 时分别先跑 push 或先跑 commit。
back message

if ${{ steps.fix.outputs.data.issue }}

/gtw back
 修复做完后回到主仓库目录 —— 下一轮的 fix 必须从 main 开始，worktree 里不允许开下一个 fix（/gtw fix 会报 already_active）。
wait final wait
