idkindstepnote
fix message 
/gtw fix ${{ args.issue }} -y
 挑一个 nightme/assigned 队列里的 issue 交给 agent 修。只有 data.issue 有值，后面的步骤才跑。
commit message

if ${{ steps.fix.outputs.data.issue }}

/gtw commit
 提交 agent 的改动。不带 error 的 nothing_to_commit（活已经提交过）正常；带 error 是真没东西可提交：instruct 让 agent 改，改完 resume 这一步。
review message

if ${{ steps.fix.outputs.data.issue }}

/review
 review 本分支与 base 的差异。链 [omp, codex] 自动降级，history 里出现 /review -a codex 即已降级。跑一半断了别 resume（resume 重发 -a omp，丢掉 -c 的续跑记录），instruct 当前 agent 发 /review -c。no_diff：instruct 让 agent 真改；base_unknown：先弄清 base；already_running：wait 一下再看。
commit-revise message

if ${{ steps.fix.outputs.data.issue }}

/gtw commit
 提交 review 后的修改。findings 只修成立且必要的，其余驳回；要修的 instruct 交给 agent 改，改完 resume 这一步。
push message

if ${{ steps.fix.outputs.data.issue }}

/gtw push
 推送分支。不带 error 的 nothing_to_push（已经在远端）正常；带 error 是本地还有没推的：instruct 让 agent 提交后 resume 这一步。
pr message

if ${{ steps.fix.outputs.data.issue }}

/gtw pr --ready
 开 PR。--ready 把 issue 从 nightme/wip 换成 nightme/ready；label 改失败只出 ⚠️，不算异常。pr_exists 正常（PR 已开过）。no_remote_branch：instruct 让 agent 推；no_commits：instruct 让 agent 提交；改完 resume 这一步。
pr-wait wait

if ${{ steps.fix.outputs.data.issue }}

60s
 等平台算完 PR 的 merge state。
pr-view message

if ${{ steps.fix.outputs.data.issue }}

/gtw pr view ${{ steps.pr.outputs.data.pr_number }}
 看 PR 现在能不能合。conflict=1 表示有冲突，是正常分支（不带 error），下面的修复步骤据此决定。
pr-fix message

if ${{ steps.pr-view.outputs.data.conflict }}

PR #${{ steps.pr-view.outputs.data.pr_number }} 有合并冲突。
在这个 worktree 里先 git fetch，再把它的 base 分支（${{ steps.pr-view.outputs.data.base_branch }}）合并进当前分支。
解掉冲突，提交并推送，让这个 PR 变成可合并。
不要关 PR，不要动 issue 的 label。
只有冲突时才让 chat 的 agent 去修。
pr-fix-wait wait

if ${{ steps.pr-view.outputs.data.conflict }}

60s
 等平台重算 merge state。
pr-recheck message

if ${{ steps.pr-view.outputs.data.conflict }}

/gtw pr view ${{ steps.pr-view.outputs.data.pr_number }}
 修完再查一次。还冲突就是没修好，本轮到此为止。
back final message

if ${{ steps.fix.outputs.data.issue }}

/gtw back
 回主仓库目录，下一轮的 fix 必须从 main 开始（worktree 里再 fix 会报 already_active）。final：轮次提前结束也照跑，保证 chat 回到主仓库。
